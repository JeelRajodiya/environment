Query path

1
Client sends SQLA dashboard sends one query to the coordinator.
2
Parse & analyzeText becomes a tree. The catalog confirms the table, columns and types.
3
OptimizeStats let it skip data: only Nov partitions, only 3 columns.
4
ScheduleThe plan is cut into fragments; each worker gets its own files.
5
ScanWorkers read columns from storage in parallel. Hot files come from SSD cache.
6
Filter & partial aggregateBatches of ~1024 values at a time. Each worker sums per region locally.
7
ShufflePartial sums move by hash(region), so one worker adds up each region.
8
ResultBillions of rows in, 4 rows back to the client.
ColumnarRead only the columns the query uses.
PruningStats skip whole files and partitions.
Parallel (MPP)Many workers, each on its own slice.
VectorizedCPU works on batches, not single rows.
